# Внесок у Six Hats Investment

Дякую за інтерес до проєкту! Цей документ описує, як зробити внесок — від простого фідбеку до значних змін у методології.

---

## 🎯 Які внески особливо вітаються

### Високий пріоритет
- **Адаптації під інші юрисдикції** (Польща, Чехія, Німеччина, ЄС загалом) — окремий файл `references/tax-<country>.md`
- **Нові приклади аналізів** у `examples/` — особливо нетипові кейси (нерухомість, крипто, ОВДП, венчурні угоди)
- **Покращення тригерної точності** — якщо помічаєте, що скіл активується там, де не треба, або навпаки не активується — повідомте
- **Локалізації** README і SKILL.md (англійська, польська)

### Середній пріоритет
- Нові правила аналізу (зараз 10) — якщо ви маєте дисциплінарне правило, яке системно покращує якість аналізу
- Покращення сценарного аналізу для нових класів активів
- Інтеграції з іншими MCP-серверами (Financial Modeling Prep, Polygon.io)

### Низький пріоритет (але корисно)
- Виправлення друкарських помилок
- Покращення форматування markdown
- Додавання скриншотів

## 📋 Як зробити внесок

### Для невеликих змін (друкарські помилки, формулювання)

1. Форкніть репозиторій на GitHub
2. Зробіть зміни напряму в браузерному редакторі GitHub
3. Створіть Pull Request з коротким описом

### Для значних змін (нові правила, адаптації)

1. **Спершу створіть Issue** з описом того, що пропонуєте. Це дозволить обговорити підхід ДО написання коду.
2. Форкніть репозиторій
3. Створіть feature-гілку: `git checkout -b feature/your-feature-name`
4. Внесіть зміни — дивіться [Стандарти якості](#-стандарти-якості) нижче
5. Протестуйте скіл у Claude (опис тестування — нижче)
6. Створіть Pull Request з посиланням на Issue

### Для багів і фідбеку

Створіть Issue з шаблоном:

```markdown
**Що сталося:**
[Опис проблеми]

**Як відтворити:**
1. Тригерна фраза:
2. Тип тези:
3. Очікувана поведінка:
4. Фактична поведінка:

**Версія Claude:** [Sonnet 4.6 / Opus 4.7 / тощо]
**Версія скіла:** [vX.Y.Z]
**Чи підключений EODHD:** так/ні
```

## ✅ Стандарти якості

### Загальні принципи

- **Жодних персональних даних** — ні в прикладах, ні в шаблонах. Використовуйте плейсхолдери (XXX, YYYY, $X,XXX)
- **Жодних інвестиційних рекомендацій** — скіл дає рамку для думання, не "купуй це"
- **Чесність над оптимізмом** — Чорний капелюх не повинен бути м'якшим за Жовтий
- **Дисципліна над риторикою** — числа і причини, а не "круто" і "перспективно"

### Для змін у `SKILL.md`

- Структура методології (7 фаз) — **не змінювати** без обговорення в Issue
- 10 правил — можна доповнювати, але не вилучати без серйозного обґрунтування
- YAML-заголовок (`description`) — критичний для активації, зміни тестувати
- Зберігайте баланс між інструкціями і свободою моделі

### Для нових прикладів у `examples/`

Структура прикладу:
```markdown
# Приклад: [Тип тези] — [Короткий опис]

[1-2 речення про сам кейс]

---

## Класифікація (Синій старт)
**Тип тези:** [з thesis-classifier.md]
**Параметри прикладу:** ...

## Білий — ключові факти
[Числа + сценарний аналіз]

## Зелений — альтернативи
[3-5 шляхів]

## Жовтий — обґрунтовані переваги
## Чорний — ризики з mitigations
## Червоний — емоційна діагностика
## Синій фініш — рекомендація + exit triggers
```

### Для адаптацій під інші юрисдикції

Створюйте окремий файл `references/tax-<country>.md` зі структурою аналогічною `tax-ukraine.md`:
- Базові ставки
- Розрахунок результату (валютний vs гривневий аналог)
- Tax events count
- Withholding tax mechanics
- Декларування

Додайте посилання в `SKILL.md` і `README.md`.

## 🧪 Як тестувати зміни

Перед створенням PR:

1. **Перепакуйте скіл у ZIP** і завантажте свою версію в Claude
2. **Запустіть мінімум 2 тестові прогони** на різних типах тез:
   - Один — directional bet (наприклад, "куплю TLT")
   - Один — long-term compounder (наприклад, "VOO на 10 років")
3. **Перевірте чеклист:**
   - ✅ Скіл активувався тільки на явну фразу
   - ✅ Запитав підтвердження перед запуском
   - ✅ Класифікував тип тези
   - ✅ Використав EODHD MCP для фактів
   - ✅ Зробив UAH сценарний розрахунок
   - ✅ Дав exit-тригери в кінці
4. **Запишіть результати** в PR description

## 📝 Style guide

### Markdown

- Заголовки з відступами через empty line
- Таблиці — для порівнянь, не для прози
- Емодзі — стримано, тільки в заголовках секцій
- Списки — короткі пункти, повний речення тільки де треба контекст

### Українська мова

- Економіко-фінансові терміни англійською в дужках при першому використанні: "хедж (hedge)", "дюрейшн (duration)"
- Цифри з пробілом-роздільником тисяч: "10 000 грн", не "10,000 грн" і не "10000 грн"
- Валюти: "$10K" або "10 000 USD" — не змішувати в одному документі
- Курс НБУ — завжди "грн за USD" (наприклад, "44.07 грн/USD"), не навпаки

### Тон

- Прямий, без зайвої ввічливості
- Числа і причини, не "цікаво" і "круто"
- Здорова критичність, але не цинізм
- Користувач — дорослий, повага до автономії рішень

## 🚫 Що НЕ прийматимуться

- Промоція конкретних продуктів, брокерів, advisors
- Зміни, що знижують критичність аналізу (наприклад, послаблення Чорного капелюха)
- Додавання конкретних "купуй/продавай" рекомендацій
- Зміни, що порушують політику Anthropic щодо Skills
- Персональні дані у прикладах або шаблонах
- Зміни, які роблять скіл менш універсальним (надмірна персоналізація під одного інвестора)
